# Master rebuild plan

The checklist is ordered. Items affecting auth, schema, checkout or deployment boundaries in phases 1–3 are sequential unless explicitly marked parallel. Each item requires a separate rollback-capable commit/PR and green relevant CI before the next phase.

- [x] **RB-001 — P0 — Phase 1. Restore reproducible baseline.** Depends on: none. Scope: Node 22, all lockfiles, CI. Acceptance: legacy, web, Worker and Supabase CI matrix runs with captured output; no high audit findings. Verify: Node 22.23.2 local matrix; CI workflow remains the merge gate. Rollback: revert only dependency/CI commit. Parallel: no.
- [x] **RB-002 — P0 — Phase 1. Prove database recovery.** Depends on RB-001. Scope: Supabase migrations, backups and RLS tests. Acceptance: fresh migration, positive/negative RLS smoke, backup/restore drill documented. Verify: local PostgreSQL bootstrap, all migrations, full smoke and custom-format dump/restore passed. Rollback: restore rehearsal snapshot; never down-migrate production blindly. Parallel: no.
- [x] **RB-003 — P1 — Phase 2. Freeze and enforce ownership boundaries.** Depends on RB-001. Scope: workspace scripts, Vercel/Firebase/Worker deployment maps, legacy guards. Acceptance: target and rollback entrypoints are documented and CI checks their identities; `apps/web` has no reverse Firebase/Prisma imports; legacy remains buildable. Verify: `check:deployment-boundaries`, migration-boundary script and dry-runs. Rollback: retain existing configs/aliases. Parallel: no.
- [x] **RB-004 — P1 — Phase 2. Classify legacy Prisma/Better Auth.** Depends on RB-003. Scope: root Vercel API, `server`, `api`, `prisma`. Acceptance: production inspection determines **KEEP**: public aliases and built legacy API handlers actively depend on this stack. Verify: Vercel inspect and Prisma validation. Rollback: no deletion; preserve current deployment. Parallel: no.
- [x] **RB-005 — P1 — Phase 3. Separate public data from personalization.** Depends on RB-003. Scope: home/catalog/category/product/header wishlist boundaries. Acceptance: anonymous home is cacheable without a user-cookie dependency; wishlist remains correct after sign-in and across matching controls. Verify: local home response returns `s-maxage=300`; guest and authenticated Chromium flows verified the header count and add/remove states with a disposable confirmed user. Rollback: feature flag or revert page boundary commit. Parallel: no.
- [x] **RB-006 — P1 — Phase 3. Make sitemap exhaustive.** Depends on RB-005. Scope: catalog data query and sitemap. Acceptance: sitemap uses a dedicated 1,000-item range query; local sitemap produced 186 product URLs and 5 category URLs, matching the production read-only Supabase counts. Catalog cache carries a shared tag and admin product/category/media mutations refresh it. Verify: typecheck, production build, local sitemap URL and Supabase count headers. Rollback: revert sitemap/cache query commit only. Parallel: no.
- [x] **RB-007 — P2 — Phase 3. Generate Supabase types.** Depends on RB-002. Scope: generated schema types and catalog/RPC callers. Acceptance: committed `database.types.ts` matches a fresh migration-generated schema; all Supabase `unknown as` casts in `apps/web/src` are removed. RPC defaults now document intentional nullable inventory values. Verify: `npm run typecheck`, production build, and a fresh database RLS smoke run. Rollback: restore previous generated type snapshot and migration. Parallel: yes, after RB-005/RB-006 interfaces freeze.
- [ ] **RB-008 — P2 — Phase 4. Build design tokens and parity references.** Depends on RB-005. Scope: CSS, visual captures/wireframes, storefront states. Acceptance: required reference artifact set exists and passes a11y/responsive review. Verify: Chrome/Firefox/WebKit, axe and three viewports. Rollback: component-level revert. Parallel: yes.
- [ ] **RB-009 — P2 — Phase 5. Complete launch admin UAT.** Depends on RB-002, RB-007. Scope: products, categories, orders, customers, media/integrations. Acceptance: all launch-critical matrix scenarios pass with server-side denial tests. Verify: integration and browser tests. Rollback: feature-flag/module revert; no data deletion. Parallel: limited.
- [ ] **RB-010 — P1 — Phase 6. Rehearse cutover.** Depends on RB-001 through RB-009. Scope: migration, R2 media reconciliation, domain, monitoring and rollback. Acceptance: backup/restore, UAT sign-off and domain rollback drill succeed. Verify: staging rehearsal. Rollback: restore prior alias and legacy deploy. Parallel: no.
- [ ] **RB-011 — P1 — Phase 7. Observe production for 14 days.** Depends on RB-010. Scope: errors, orders, notifications, CWV and security events. Acceptance: no rollback-critical incidents; p75 LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 or agreed exception. Verify: dashboards and order reconciliation. Rollback: execute RB-010 rollback procedure. Parallel: no.
- [ ] **RB-012 — P2 — Phase 8. Archive proven legacy.** Depends on RB-011. Scope: items in `CLEANUP_REPORT.md`. Acceptance: each archive/delete candidate has proof and backup; no live deployment references. Verify: CI, deploy dry-run and rollback build. Rollback: restore archived bundle/commit. Parallel: no.
- [ ] **RB-013 — P3 — Phase 9. Plan extended admin.** Depends on RB-011. Scope: variants, promos, bulk operations, CMS, analytics and audit history. Acceptance: prioritized requirements, ownership and authorization model approved. Verify: design/technical review. Rollback: n/a; planning only. Parallel: yes.
