Нужно реализовать на главной странице сайта интерактивный scroll-driven блок категорий.

Сначала внимательно изучи текущий проект, структуру главной страницы, существующие компоненты, стили, роутинг, категории товаров, названия категорий, ссылки на страницы категорий и используемый стек.

Не меняй архитектуру проекта без необходимости. Не ломай существующий дизайн, адаптивность, SEO, навигацию или функциональность магазина.

ЦЕЛЬ

На главной странице должен появиться большой интерактивный контейнер высотой примерно в экран, внутри которого центральным объектом является апельсин.

Апельсин символизирует исходный фрукт, из которого бренд производит разные типы продукции.

При вертикальном скролле пользователь должен последовательно видеть, какие продукты можно сделать из апельсина.

Пример последовательности:

Фруктові чіпси

Сиропи

Льодяники

Пудри

Другие реальные категории магазина, если они уже существуют в проекте

Обязательно сначала проверь реальные категории сайта и используй существующие названия и URL.

Не придумывай ссылки, если реальные маршруты уже есть.

ОСНОВНАЯ МЕХАНИКА

Когда пользователь доходит до этого блока, обычный вертикальный скролл должен временно превратиться в последовательную анимацию категорий.

Контейнер должен оставаться визуально закреплённым на экране во время прохождения всех состояний.

Используй GSAP + ScrollTrigger, если GSAP уже есть в проекте.

Если GSAP отсутствует, можно установить:

gsap

Используй ScrollTrigger.

Не используй Three.js, WebGL или тяжёлые 3D-библиотеки без необходимости.

СОСТОЯНИЕ 1

В центре экрана расположен крупный апельсин.

За апельсином крупным типографическим текстом находится название категории:

ФРУКТОВІ ЧІПСИ

Текст должен визуально находиться позади апельсина.

Часть букв может перекрываться апельсином для создания глубины.

Вокруг апельсина должны появляться изображения апельсиновых чипсов.

Они должны выглядеть так, будто вылетели из апельсина.

Использовать примерно 8–14 элементов.

Не использовать Math.random непосредственно при каждом render.

Создай заранее определённый набор позиций, scale, rotation и направления, чтобы композиция выглядела случайной, но оставалась красивой и предсказуемой.

ПЕРЕКЛЮЧЕНИЕ КАТЕГОРИИ

Когда пользователь скроллит дальше:

Апельсин вращается вокруг своей оси.

Допустимо вращение примерно 180–360 градусов.

Можно добавить небольшой scale / squash / bounce эффект.

Старые продукты начинают улетать от центра за пределы контейнера.

Они одновременно уменьшаются или исчезают по opacity.

Название старой категории исчезает.

Название следующей категории появляется.

Из центра апельсина вылетают продукты новой категории.

Апельсин остаётся тем же центральным объектом.

Например:

Фруктові чіпси
→ чипсы улетают

Сиропи
→ из апельсина вылетают бутылочки апельсинового сиропа

Льодяники
→ бутылочки улетают
→ появляются апельсиновые леденцы

Пудри
→ появляются элементы, визуально представляющие апельсиновую пудру

И так далее.

ВАЖНО

Все продукты во всех состояниях должны быть именно продуктами, сделанными из апельсина.

То есть смысл сцены:

ОДИН ФРУКТ → МНОГО ВИДОВ ПРОДУКЦИИ

Апельсин всегда остаётся центральным символом.

SCROLL

Не делай анимацию чрезмерно чувствительной.

Пользователь не должен одним движением колеса мыши случайно перескочить через все категории.

Переходы должны ощущаться как отдельные состояния.

Можно использовать scrub ScrollTrigger, но визуально каждая категория должна иметь достаточно пространства по scroll progress.

Например:

section height:
количество категорий × 100vh

Внутренний визуальный контейнер:

position: sticky
или
ScrollTrigger pin

На каждой равной части progress переключается одна категория.

После последней категории pin должен закончиться, и страница продолжает обычный вертикальный скролл.

Обязательно корректно поддержать:

mouse wheel
trackpad
touch scroll

АПЕЛЬСИН

Апельсин должен быть крупным главным объектом.

Desktop ориентировочно:

30–40vw

но с адекватными max-width.

Mobile:

примерно 55–70vw.

Он должен оставаться визуальным центром композиции.

Апельсин должен быть кликабельным.

При клике нужно открыть страницу текущей активной категории.

Курсор:

cursor: pointer

Для desktop можно добавить очень лёгкий hover:

scale примерно 1.02–1.05

Не делать дешёвые glow/shadow эффекты.

ТЕКСТ КАТЕГОРИИ

Название категории должно быть большим.

На desktop оно может занимать значительную часть ширины экрана.

Пример:

font-size: clamp(64px, 10vw, 180px)

Используй существующую типографику сайта.

Текст располагается позади апельсина.

z-index примерно:

background
category title
orange
flying products
foreground UI

Можно часть продуктов расположить перед апельсином, часть за ним для глубины.

ПРОДУКТЫ

Все элементы должны использовать position: absolute.

Для каждой категории сделай конфигурацию примерно такого типа:

{
id,
title,
href,
assets,
positions
}

Каждый декоративный элемент должен иметь:

x
y
rotation
scale
optional depth

Пример:

{
x: "-32vw",
y: "-20vh",
rotation: -25,
scale: 0.8
}

Не допускай, чтобы все предметы собирались в центре.

На mobile количество элементов можно уменьшить.

АДАПТИВ

Desktop:
полная композиция

Tablet:
немного уменьшить количество объектов

Mobile:
примерно 5–8 объектов вокруг апельсина

Название категории может переноситься на две строки.

Не допускай горизонтальный scroll.

Контейнер:

overflow: hidden

PERFORMANCE

Оптимизируй анимацию.

Используй:

transform
opacity

Не анимируй тяжёлые CSS свойства вроде width / height / top / left в реальном времени.

Используй will-change только там, где оправдано.

Все изображения должны иметь адекватный размер.

Использовать WebP/AVIF/PNG с прозрачным фоном там, где это необходимо.

Не загружать изображения в разрешении 4000px, если на экране они отображаются 300px.

PREFERS REDUCED MOTION

Обязательно предусмотреть:

prefers-reduced-motion

Для таких пользователей показывать статическую или сильно упрощённую версию блока.

ACCESSIBILITY

Апельсин должен быть интерактивным элементом через:

button
или
Link

а не просто div с onClick.

Добавить корректный aria-label:

Перейти до категорії {categoryName}

Декоративные продукты должны иметь:

aria-hidden="true"

СТРУКТУРА КОДА

Не писать всю сцену непосредственно в page.tsx.

Сделай отдельный компонент примерно:

components/home/OrangeCategoryShowcase.tsx

или в существующей структуре проекта в наиболее логичном месте.

Конфигурацию категорий желательно вынести отдельно:

orangeShowcaseCategories.ts

или аналогично.

Компонент должен быть легко расширяемым.

Чтобы для добавления новой категории было достаточно добавить конфигурацию:

{
title,
href,
productImages
}

ASSETS

Сначала проверь assets проекта.

Если изображения апельсина или продукции уже существуют — используй их.

Если нужных прозрачных изображений нет:

НЕ создавай фальшивые placeholder-картинки внутри финального интерфейса.

Создай понятную структуру assets и временно используй только те реальные изображения, которые доступны.

Оставь комментарий или список файлов, которые нужно будет заменить на финальные изображения.

Пример:

/public/showcase/orange/orange.webp
/public/showcase/orange/chips/
/public/showcase/orange/syrup/
/public/showcase/orange/candy/
/public/showcase/orange/powder/

ВИЗУАЛЬНЫЙ СТИЛЬ

Перед реализацией изучи текущий дизайн сайта.

Новая сцена должна выглядеть частью существующего проекта, а не отдельным шаблоном.

Сохрани:

цветовую палитру
типографику
border-radius
общий характер дизайна
визуальный язык бренда

При этом сцена должна выглядеть более премиально и выразительно.

Не использовать:

generic gradients
неон
лишний glassmorphism
случайные карточки
стоковый SaaS-дизайн

Главный визуальный акцент — апельсин и продукция.

ДОПОЛНИТЕЛЬНЫЙ ЭФФЕКТ

При первом появлении блока можно показать только апельсин.

После небольшого scroll progress появляется первая категория и из апельсина начинают вылетать чипсы.

Это должно визуально объяснять концепцию:

из одного фрукта бренд делает много различных продуктов.

ВАЖНО ПО UX

Пользователь должен понимать, что апельсин можно нажать.

Можно использовать очень небольшую подпись:

Перейти до категорії →

но она не должна конкурировать с основной композицией.

На mobile обязательно сделать взаимодействие очевидным.

ПОРЯДОК РАБОТЫ

Изучи проект.

Найди главную страницу.

Найди существующий список категорий.

Найди реальные URL категорий.

Найди доступные изображения.

Определи лучшее место для нового блока.

Реализуй компонент.

Добавь GSAP ScrollTrigger.

Реализуй responsive behaviour.

Реализуй reduced-motion.

Проверь TypeScript.

Проверь build.

Исправь console errors.

Проверь отсутствие horizontal overflow.

Проверь mobile.

Проверь desktop.

Проверь переход по клику на текущую категорию.

После реализации покажи:

какие файлы были созданы;

какие файлы изменены;

какие категории подключены;

какие изображения используются;

какие assets ещё нужно подготовить;

краткое описание механики ScrollTrigger;

результат build/typecheck.

Не удаляй существующие секции главной страницы без необходимости.

Если новая сцена заменяет существующий блок категорий, сначала проверь его назначение и переиспользуй существующие данные/ссылки вместо создания дублей.
